# 字幕延迟统计

主窗口点击“延迟统计”，可在识别过程中查看统计，也可停止后查看、导出 JSON 或清空。数据只驻留内存；本次程序运行中最多保留 512 条记录，关闭程序即清除。一个音频片段与其产生的每条字幕各占一条记录，因此 512 不是字幕条数。自动淘汰最早记录，各阶段的样本数可能不同。统计不保存音频、台词或人物信息，导出的 JSON 由用户自行保留或删除。

记录使用 `Stopwatch` 单调时钟，音频片段关联其产生的字幕 ID。两句快速接话共享一次识别耗时，翻译与显示分别计时；不会把一次识别重复计入平均值。原文隐藏时不标记为已经显示；译文未真正写入当前可见字幕控件时不标记为已经显示。

| 指标 | 含义 |
|---|---|
| 估计语音结束 → 分段就绪 | 分段器最后一次判定有声/语音的帧结束到输出片段，包含尾部静音等待 |
| 识别排队 | 片段入队到开始识别 |
| 识别 | 实际识别客户端请求，含音频传递、ASR 与声线检测 |
| 翻译排队 | 识别完成到翻译阶段开始，包含队列背压 |
| 翻译 | 本地翻译调用及会话上下文重置；旁路、空译文、失败也记录阶段耗时 |
| 识别/翻译完成 → 控件更新 | 结果可用到其第一次写入当前显示的字幕控件；可能包含等待其他字幕显示的时间 |
| 片段入队 → 控件更新 | 处理阶段总等待；适用于实时输入和离线回放 |
| 估计语音结束 → 控件更新 | 有实时采集时钟的片段才统计；同一片段两句共用片段的估计结束时间 |

“控件更新”是 WPF UI 线程设置字幕文字，不是显示器实际呈现。端点由采集起点和样本位置映射到单调时钟，受音频缓冲、时钟偏差、背景音乐以及分段器判断影响，不是人工标注的真实句末。设备缓冲误差未独立校准；映射到未来的端点记为缺失，不伪造零延迟。离线录音不伪造采集时间，所以没有句末端到端指标。分段规则和保留的音频内容没有改变。

计数覆盖保留记录中的丢弃、空识别、失败、取消与停止后拒收。翻译阶段完成包含跳过；不能把这个数量当作有效中文译文数量。指标显示平均值、P50、P95 和最大值；缺失数据显示横线。清空时正在执行的旧记录不会在完成后重新出现，新入队片段正常统计。

## 声线计算优化

主 ASR 与声线模型权重不变。可用逻辑 CPU 数达到 8 时，声线 ONNX 默认使用 4 个内部线程，否则沿用 2 个；Python `SpeakerEmbedding(..., intra_op_num_threads=2)` 可用于实验回退。Windows 上此探测不反映人为设置的进程 affinity 限制。fbank 配置复用并移除多余复制，每个窗口仍独立计算特征和均值。候选、阈值、窗口与 650 ms 预算均不变。

这是以额外 CPU 并行工作换取等待时间减少。当前笔记本上的独立嵌入测试中，CPU 总时间约增加 23%；游戏争抢 CPU 时的效果仍需实测，不代表总计算量或功耗降低。

2026-10-25 同机两轮反序、70 条录音的对照中，普通配置识别总耗时中位数 30.29 → 24.29 秒（减少 19.8%），保留上下文配置 33.89 → 26.54 秒（减少 21.7%）；两轮所有文本、边界和调用数一致。数据属于经模型筛选的开发样本，不是独立准确率金标；没有据此宣称准确率提升。

详细结果在 `artifacts/speaker-latency-20261025/`，可运行预览版在 `artifacts/speaker-latency-preview/`。该次实验没有修改用户模型选择、历史数据或实验选项默认值，也没有进行训练。实验结果和预览产物仅保留在本地，不随仓库分发；软件发布信息以仓库版本和 Release 说明为准。
